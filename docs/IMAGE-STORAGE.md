# 图片存储

团队开发统一连接共享 MinIO，使用独立私有桶 `glucopilot`。图片文件保存在 MinIO，MySQL 的 `media_file` 保存对象键、桶名、上传者、业务类型及状态；GitHub 只保存代码。不需要在不同电脑之间反复上传图片。

每位成员在本机忽略的 `.env` 填写下面这些键，值由存储负责人提供，不能提交到仓库：

```dotenv
STORAGE_PROVIDER=minio
MINIO_ENDPOINT=http://minio.example.internal:9000
MINIO_ACCESS_KEY=replace-locally
MINIO_SECRET_KEY=replace-locally
MINIO_BUCKET=glucopilot
```

上述配置对应 `dev` profile。合入主线后，`prod`默认也使用MinIO，并保留按`STORAGE_PROVIDER`选择OSS的配置；生产必须单独核对目标服务、桶及凭据，不能直接复制个人配置。

所有成员需要使用同一套媒体登记数据与存储目标。仅拉取 GitHub 代码不会同步个人数据库、`.env` 或图片。局域网联调时，后端需要访问MinIO；MinIO凭证现在返回后端同源的一次性PUT代理`/api/v1/media-files/minio-uploads/{token}`，小程序/管理端只需访问后端，Content-Type须为application/octet-stream，后端按凭证大小写入真实对象。OSS等外部预签名上传仍不额外注入Content-Type以免破坏签名。服务器关机、网络隔离或切换到其他桶仍会导致图片无法读取。

头像上传继续走“凭证 → PUT → 登记 → 更新个人资料”。登记返回稳定的 `/api/v1/media-files/avatars/{mediaId}`，小程序将其解析为当前后端地址，由后端从私有桶读取字节。数据库及用户缓存保留这个身份地址，展示时下载的手机临时路径不写回资料。不为显示头像公开整个桶，不把短期签名下载链接保存为长期头像地址。

餐食、血糖照片、社区投稿等仍走各自业务接口和权限校验，不能借用头像读取接口公开；本次未改变这些业务的可见性。

## 从本机 local 切换

1. 确认原 `LOCAL_UPLOAD_DIR` 和已登记媒体，核对大小及已有内容哈希；先备份 `.env`、`media_file`、`user_profile`。
2. 在确认的目标桶按原 `storage_key` 复制可用媒体，逐一回读并比对 SHA-256。遇到同名不同内容的对象立即停止，不覆盖；保留本机原文件，未登记文件不擅自公开或绑定用户。
3. 停止开发后端，避免切换期间新增上传。重新核对媒体及个人资料快照，一致后用事务更新目标媒体的桶定位和对象地址，并将匹配的旧头像改为稳定地址。媒体ID、上传者、业务类型及关联不变。
4. `.env` 改为目标 MinIO 后重新启动，重新编译小程序。验证旧头像 HTTP200 且字节与原图一致、非头像媒体不能从该公开入口读取，再验证预签名上传和服务端回读。

回退也需要暂停上传：先恢复相同备份中的媒体定位和个人头像，再恢复相应的本机存储配置。不能只改 provider 而保留另一套存储的登记记录。切换后产生的新文件应单独核对后再处理。

## 本机迁移验收（2026-10-21）

用户确认目标服务和独立桶后，首批迁移10张有效登记图片（2张头像、5张餐食、3张血糖照片），全部按原对象键复制且SHA-256一致。10条媒体保留原ID及归属，仅变更桶、对象地址和数据库自动维护的修改时间；2条匹配头像改为稳定地址。本机11个原文件全部保留。

后续排查发现剩余1张为已登记食品图，旧记录的桶名为空，首批筛选因此漏掉，并非未登记文件。已备份该登记至工作区`.tmp/legacy-food-image-backup-20261021-144054`，按原对象键补复制并回读校验SHA-256，仅补齐桶名，保留ID、归属和原文件。食品图后端读取HTTP200且与原图一致；新食品图登记同时保存桶名，避免后续遗漏。至此这11张历史图片均已复制并核对，后续新增文件不在该历史清单内。

本机备份位于工作区 `.tmp/minio-migration-backup-20261021-101619`，包含当时私密环境配置和完整媒体/个人资料快照；迁移清单为 `.tmp/minio-migration-manifest.json`。这些文件含私密数据，不提交GitHub，也不代替共享服务自身的持久化和备份。

使用真实 MinIO 已验证预签名PUT及回读，临时验证对象已清理；匿名直接读取桶内头像返回403。用户重启后，当前8080服务两张旧头像均HTTP200，字节与原文件一致；用餐食/血糖媒体ID请求头像入口返回404。

MinIO明确返回NoSuchKey/NoSuchObject时才按对象不存在处理；网络、权限或服务异常提示“文件存储暂时不可用，请稍后重试”，不误报成未上传或不存在。最终重启后健康检查HTTP200，头像及食品图业务读取复核通过；这是当时的连接状态，仍需保持共享服务运行与网络可达。
