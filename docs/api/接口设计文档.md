## 1. 引言与生产目标

### 1.1 文档目的

本文档为 **生产环境** HTTP API 契约，供微信小程序、运营后台与服务端联调、测试与验收。数据模型严格对齐 merged-v2 DDL；枚举一律数字落库/传输，中文仅用于端上展示。

### 1.2 系统边界

| 端 | Base URL | 身份 | 数据范围 |
| --- | --- | --- | --- |
| C 端（微信小程序） | `https://{host}/api/v1` | 微信 `code` / 手机号+短信 → `user_session` | **仅本人** |
| 运营后台 | `https://{host}/admin/v1` | 账号密码 → `ops_session` + RBAC | 全量运营；健康明细限权 |

> C 端 **无密码体系**。账号安全页仅支持绑定/换绑手机号与会话管理，不提供「修改密码」。

### 1.3 相对原型的生产要求

| 项 | 生产要求 |
| --- | --- |
| 血糖 / 饮食 | **分接口、分表**；禁止混写为单一本地结构直落库 |
| 媒体 | 照片/语音必须先上传对象存储并登记 `media_file`，业务只存 `mediaId` |
| OCR | 异步任务 `ocr_task`；客户端轮询后再确认入库 |
| AI 对话 | 多会话 + `clientMsgId` 幂等 + SSE 流式；上下文写入 `chat_context` |
| 枚举 | API 传数字；展示层映射中文（见附录） |
| 配置 | 血糖阈值、免责声明、主题默认值来自 `sys_config` / `app-config` |
| 审计 | B 端写操作 + 健康档案读/导出必须写 `ops_audit_log` |

## 2. RESTful 与安全规范

### 2.1 REST 原则

| 原则 | 约定 |
| --- | --- |
| 资源 | URL 名词复数，如 `/glucose-records`、`/chat-sessions/{id}/messages` |
| 动词 | `GET` 查 / `POST` 建 / `PUT` 全量 / `PATCH` 部分 / `DELETE` 软删 |
| 无动词路径 | 禁止 `/create`、`/update`；状态变更用 `PATCH` 或子资源 |
| 幂等 | 见「幂等接口清单」 |
| 状态码 | 三位 HTTP 表示协议语义；五位 `code` 表示业务细分（见「统一响应与错误码总表」） |

### 2.2 安全（生产强制）

| 项 | 约定 |
| --- | --- |
| 传输 | 仅 HTTPS；HSTS 由网关开启 |
| 鉴权 | `Authorization: Bearer {accessToken}` |
| C 端 Token | 写入 `user_session.access_token`；默认 **604800 秒（7 天）**；**无 refreshToken**（过期重新登录） |
| B 端 Token | 写入 `ops_session`；默认 **7200 秒（2 小时）**；`GET /admin/v1/auth/profile` 或续期接口可刷新滑动过期（实现二选一，锁定为：**访问时滑动续期，上限单次会话 8 小时**） |
| Token 失效 | 登出 / 账号禁用 / 注销中：对应会话行 `is_valid=0`（**会话表失效**，非 JWT 黑名单）；校验时查库 |
| 越权 | C 端写操作 `userId` **仅取自 Token**，忽略/拒绝 body 中的他人 ID |
| 脱敏 | B 端列表手机号默认掩码；完整手机号需明确权限 |
| 限流 | 见「限流基线」；超限 HTTP `429` / `42901` |
| B 端锁定 | 连续失败 **5 次**锁定 **10 分钟**（按账号）；锁定中返回 `42901` |
| 短信 | 验证码 6 位、有效期 5 分钟、单次使用；同号 60s 冷却；日上限可配；优先 Redis TTL |
| 密钥 | AI `api_key_cipher` 禁止明文响应；OSS 预签名 URL ≤ 30 分钟 |
| 运营口令 | 仅 HTTPS 提交；库表只存 `password_hash`（bcrypt/argon2）；禁止明文落库/日志/审计 |
| 健康数据下载 | 导出/备份下载链接 ≤ 10 分钟；访问记审计 |

## 3. 通用约定

### 3.1 请求头

| Header | 必填 | 说明 |
| --- | --- | --- |
| `Authorization` | 鉴权接口：是 | `Bearer {accessToken}` |
| `Content-Type` | Body 有 JSON：是 | `application/json;charset=UTF-8`；上传为 `multipart/form-data` |
| `X-Request-Id` | 否 | 客户端 UUID；服务端回传并写入 B 端审计 |
| `X-Idempotency-Key` | 见「幂等接口清单」 | 关键写操作幂等键 |

### 3.2 统一响应与错误码总表（唯一权威）

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "requestId": "b1f0c8e2-4a3d-4c1e-9f0a-123456789abc"
}
```

**分层约定**

| 层 | 形态 | 作用 |
| --- | --- | --- |
| HTTP 状态码（三位） | `200/400/401/403/404/409/429/500` | 对外标准协议语义；网关/监控/客户端先认 |
| body `code`（五位） | `0` 或 `4xxxx/5xxxx` | 内部业务细分；同族前三位对齐 HTTP |

成功：**HTTP 200** 且 **`code=0`**（不用 `20000`）。

#### 错误码总表

| HTTP | code | 含义 | 典型触发 |
| --- | --- | --- | --- |
| 200 | 0 | 成功 | — |
| 400 | 40000 | 参数格式/类型/必填校验失败 | 缺字段、类型错误、日期格式非法；`data.fields` 可带字段明细 |
| 400 | 40001 | 业务校验失败 / 凭证错误 | 验证码错误、节点餐点类型不匹配、开关关闭、口令错误（防枚举统一文案） |
| 401 | 40100 | 未登录 / Token 失效 | 无 Token、会话 `is_valid=0`、已过期 |
| 403 | 40300 | 无权限 / 账号禁用 / 注销中 | RBAC 不足、`accountStatus∈{0,2}`、运营停用 |
| 404 | 40400 | 资源不存在或不属于当前用户 | 路径合法但记录不存在或越权伪装成不存在 |
| 409 | 40900 | 冲突 | 唯一键、乐观锁、openid/手机号已被占用 |
| 429 | 42901 | 限流 / 登录锁定 | 超 QPS、短信冷却、B 端连续失败锁定 |
| 500 | 50000 | 系统异常 | 未捕获异常、下游超时且不可归类 |

> 各接口 **不再重复** 展开错误码说明；下文统一写：**错误码见「统一响应与错误码总表」**。接口可另列「特有业务码」行（若仅使用上表通用码可省略）。

未登录调需鉴权接口 → **401**；无权 → **403**；路径有但记录不存在 → **404**。禁止「功能未做」类自定义码。

### 3.3 参数表规范

每个接口参数按位置拆分，表格统一四列：

| 列 | 含义 |
| --- | --- |
| 字段名 | Path / Query / Body / Header 名 |
| 类型 | 如 `String(20)`、`Int`、`Long`、`Boolean`、`Object`、`Array` |
| 必填 | **是** / **否**；条件必填在说明中写清 |
| 说明 | 约束、枚举、默认值、空值语义 |

**空值约定**：`PATCH` 省略字段 = 不改；显式 `null` = 置空（仅可空字段）；空字符串 `""` 与 `null` 不同（字符串字段按「有值的空串」写入，禁止用 `""` 表示未传）。

### 3.4 分页与非分页列表

**分页 Query**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| pageNum | Int | 否 | 默认 `1`，从 1 起 |
| pageSize | Int | 否 | 默认 `10`，最大 `100` |
| orderBy | String | 否 | 白名单字段；非法 → `40000` |
| orderDirection | String | 否 | `asc` / `desc`，默认 `desc` |
| lastId | Long | 否 | 深分页游标；当 `pageNum * pageSize > 10000` 时必填，否则 `40000` |

**分页响应 `data`（强制统一）**

```json
{
  "pageNum": 1,
  "pageSize": 10,
  "total": 128,
  "pages": 13,
  "records": []
}
```

**非分页（全量）接口** —— 响应 `data` 为数组或 `{ "records": [] }`，**不含** `pageNum/pageSize/total`：

| 接口 | 返回形态 | 说明 |
| --- | --- | --- |
| `GET /dict/glucose-nodes` | `data: Node[]` | 启用节点，条数固定约 9 |
| `GET /banners` | `data: Banner[]` | 上架且有效期内；建议 ≤ 8 |
| `GET /food-categories` | `data: Category[]` | 启用分类 |
| `GET /app-config` | `data: { configs: [...] }` | 按 groups 过滤 |
| `GET /news/{id}/actions` | `data: { isLiked, isCollected }` | 单对象 |
| `GET /auth/sessions/current` | `data: { valid, expiresIn }` | 单对象 |

分页接口：`GET /news`、`GET /foods`、`GET /feedbacks`、`GET /glucose-records`、`GET /meal-records`、`GET /chat-sessions`、`GET /chat-sessions/{id}/messages`、`GET /export-tasks`、`GET /backups`、`GET /ocr-tasks`、`GET /user-memories` 及 B 端各类列表。

### 3.5 幂等接口清单

| 接口 | 幂等键 | 重复请求行为 |
| --- | --- | --- |
| `PUT /glucose-records/by-node` | 业务键 `(userId, recordDate, nodeCode)` | 覆盖写同一条；返回最新实体 |
| `PUT /meal-records/by-node` | 同上 | 覆盖写；明细按请求全量替换（若带 `foodItems`） |
| `POST .../messages` | Body `clientMsgId`（必填） | 唯一冲突视为成功，返回已有消息 |
| `POST /auth/wechat/sessions` 等登录 | 无 | 每次签发新会话行（允许多端） |
| `POST /export-tasks` | Header `X-Idempotency-Key`（强烈建议） | 同键 24h 内返回同一任务 |
| `POST /backups` | Header `X-Idempotency-Key`（强烈建议） | 同上 |
| `POST /ocr-tasks` | Header `X-Idempotency-Key`（建议） | 同键返回同一任务 |
| `POST .../completions` | 依赖已落库消息的 `clientMsgId` / `replyToMsgId` | 禁止无键盲目重放；客户端断线续传以消息为准 |
| `PUT /news/{id}/actions` | 业务键 `(userId, newsId)` | 覆盖点赞/收藏状态 |
| `POST /backups/{id}/restore` | Header `X-Idempotency-Key`（强烈建议） | 同键不重复叠加恢复副作用计数异常 |
| B 端发布/回复/推送执行 | Header `X-Idempotency-Key`（必填） | 同键返回首次结果 |

未列入的 `POST` 默认 **非幂等**（重复可能产生多条）；客户端应避免无意义重试，或自带幂等键。

### 3.6 时间、布尔、更新语义

- 时间：`yyyy-MM-dd HH:mm:ss.SSS`（北京时间）；日期 `yyyy-MM-dd`。
- 布尔：JSON `true`/`false` ↔ 库 `0/1`。
- `PATCH`：只更新出现的字段；显式 `null` 置空可空字段。
- 乐观锁：更新类接口可带 `gmtModified`，冲突 → HTTP `409` / `40900`。

### 3.7 命名

URL 小写连字符；JSON `camelCase`；库 `snake_case`。

### 3.8 限流基线（可按环境调参）

| 场景 | 限额 |
| --- | --- |
| C 端微信/手机登录 | 10 次/分钟/IP；手机登录额外 5 次/分钟/手机号 |
| 发短信 | 1 次/60s/手机号；10 次/日/手机号 |
| OCR 创建 | 20 次/小时/用户 |
| AI completion | 30 次/小时/用户（受 `ai.chat.enabled` 总开关控制） |
| B 端登录 | 5 次/分钟/账号；连续失败锁定 10 分钟 |
| 通用查询 | 60 QPS/用户或账号 |

## 5. C 端接口（/api/v1）

除认证、公开配置、字典、已发布内容外，均需登录。`userId` 始终取自 Token。  
**错误码见「统一响应与错误码总表」**（各接口仅补充特有说明）。

### 5.1 认证与会话

#### 5.1.1 `POST /auth/wechat/sessions`（匿名）

| 位置 | 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| Body | code | String(128) | 是 | `wx.login` 临时凭证 |

**响应 `data`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| accessToken | String | 会话令牌 |
| expiresIn | Int | 剩余有效秒数，默认 604800 |
| isNewUser | Boolean | 是否本次新建账号 |
| accountStatus | Int | 1 正常；0/2 见下 |
| needDisclaimer | Boolean | 是否需签署当前免责声明版本 |

**特有错误**：`accountStatus∈{0,2}` → `40300`；`code` 无效 → `40001`（文案统一防枚举）。

新用户事务内创建空的 `user_profile` / `user_health` / `user_setting`。

#### 5.1.2 其余认证接口

| 方法 | 路径 | 鉴权 | Body 必填字段 | 说明 |
| --- | --- | --- | --- | --- |
| POST | `/auth/wechat/bind` | 登录 | `code` | 绑定微信；冲突 `40900`；不自动合并账号 |
| POST | `/auth/sms/codes` | 匿名 | `phone`，`scene`=`login`\|`bind` | 发短信 |
| POST | `/auth/phone/sessions` | 匿名 | `phone`，`verifyCode` | 手机登录；成功 `data` 同微信登录 |
| DELETE | `/auth/sessions/current` | 登录 | — | 当前会话 `is_valid=0` |
| GET | `/auth/sessions/current` | 登录 | — | `{ "valid": true, "expiresIn": 123456 }` |

账号绑定冲突：**HTTP 409** / `40900`；**不自动合并账号**。

## 7. 生产硬约束

（与库文档第 5 章一致；错误码不在此重复，见「统一响应与错误码总表」。）

1. 血糖节点必须非餐点；饮食节点必须餐点。

5. 默认 AI 模型全局唯一。  
6. 点赞/收藏同步冗余计数。  
7. 健康数据下载短时效 + 审计。  
8. 会话失效以 `*_session.is_valid=0` 为准。
